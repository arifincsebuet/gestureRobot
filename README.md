# Reproducibility artifact: Risk-Asymmetric Gesture Authorization (RAGA)

This repository accompanies the paper **"Risk-Asymmetric Gesture
Authorization: Decoupling Stop and Start Authority in IoT and Human-Robot
Environments,"** submitted for double-anonymous review. It reproduces every
numeric claim, table, and figure in the paper's Experimentation section, and
includes a runnable implementation of the physical three-node testbed
described there.

The paper is held to ICRA's hard 8-page limit, so it reports E1-E7 and
E12-E14 in full and defers four supporting experiments to this repository:

| | |
|---|---|
| **E8** | numerical illustration of the Theorem 1 calibration-regret bound |
| **E9** | decision-throughput benchmark against published streaming and CEP figures |
| **E10** | ablation of the quorum and liveness mechanisms |
| **E11** | stranger-confidence spread sweep behind E1's cliff (Fig. 2b) |

Everything below covers all fourteen; nothing about E8-E11 is different in
how it is generated or checked.

> **Anonymity note.** This repository is anonymized for double-anonymous
> review: no author names, affiliations, institutional identifiers, or local
> paths appear in any file, and the committed figures carry no metadata beyond
> the matplotlib version. Do not add attribution before the review period ends.

## What's here

```
parameters.py             EVERY numeric constant, with the published source it comes from
raga_experiments.py       Monte Carlo simulation for E1-E14 (~3 min on a laptop core)
merge_figures.py          combines per-experiment figures into the paper's multi-panel figures
verify_paper_claims.py    checks every number the paper states against regenerated data
dataset/                  reference CSVs from a verified run (see "Reference data" below)
figures/                  one plot per experiment, as raga_experiments.py emits them
fig/                      multi-panel figures assembled by merge_figures.py (4 of these are printed)
requirements.txt          numpy, matplotlib (simulation only)
testbed/                  physical three-node UDP testbed (pure standard library)
```

Both image directories are committed so a reviewer can match every figure in
the paper against artifact output without running anything; both are fully
regenerated by the two commands in section 1.

The paper prints four of the panel figures — `merged_trap_spread.png`,
`merged_negresults.png`, `merged_testbed_phase.png` and
`raga_architecture_simple.png`. The rest cover the artifact-only experiments
and the material cut for length. On a clean rerun, all four printed figures
come back **byte-identical** to the committed copies; the only files that
change are the two panels containing the E9 throughput measurement, which is
wall-clock timing and cannot be seeded (see "Reference data").

## Where the numbers come from

`parameters.py` is the file to read first. Every constant in the evaluation
lives there, and each carries either a citation to a public source or an
explicit `[MODEL]` label naming the experiment that sweeps it. Nothing in the
simulation invents a number. In summary:

| Parameter | Source |
|---|---|
| $\Lambda$ (harm) | NSC *Injury Facts* 2024: \$1,540,000 per workplace death, \$48,000 per medically consulted injury |
| $\alpha$, $\varphi$ (needless stop, re-gesture) | recovery durations priced at Siemens *True Cost of Downtime 2022* sector rates (automotive \$2M/h, FMCG \$39k/h) and the BLS manufacturing wage (\$36.87/h, Jul 2026) |
| $c_{\mathrm{floor}}$ | NIST FRTE reporting operating point FMR $=10^{-3}$, where leading 1:N algorithms reach FNMR 0.15% on galleries above $10^7$ |
| operator confidence | the measured constrained/unconstrained recognition gap: IJB-C TAR@FAR$=10^{-4}$ of 96-98% vs IJB-S rank-1 50-73%, TinyFace rank-1 64-75% |
| $\rho_{\min}$ | the 100 ms World Athletics false-start threshold (commissioned study measured auditory reactions to 80 ms) |
| $\rho_{\max}$, reflex distribution | Olson & Sivak 1986 surprise-hazard percentiles (median 1.1 s, 95th 1.6 s), upper bound 2.5 s from Broen & Chiang's observed 2.44 s maximum |
| gesture polarity error | swept 0-15%, bracketed above by IPN Hand's 13.7% error for the best model on realistic data |
| clock skew | measured NTP/PTP regimes (PTP sub-microsecond; NTP LAN <0.01 ms; NTP WAN <1 ms) |

Three things remain modelling choices and are swept rather than asserted: the
population mix of operators/strangers/impostors, the recovery durations that
convert downtime rates into $\alpha$ and $\varphi$, and the severity mixture
behind the AGV's $\Lambda$. `parameters.py` labels each one.

## 1. Reproducing the simulation results (E1-E14)

```bash
pip install -r requirements.txt
python raga_experiments.py       # writes ./figures/*.png and ./dataset/*.csv
python merge_figures.py          # combines pairs of figures into the paper's panel figures
python verify_paper_claims.py    # checks every number above against the manuscript
```

`verify_paper_claims.py` is the artifact the paper itself refers to ("Every
numeric claim below is verified automatically against regenerated data by a
released script that also encodes structural guards, failing if any headline
finding stops holding," Sec. IV-C). It hardcodes
every number as printed in the manuscript, regenerates the data independently
from `raga_experiments.py`'s output, and compares the two — it does not read
its expected values from the same run it's checking. A clean run prints:

```
========================================================================
Verified 141 numeric claims against dataset/
========================================================================

All paper claims are consistent with the generated data.
```

Beyond simple number matching, it also checks the paper's *structural*
claims — for example, that the polarity-only ablation is actually worse than
full RAGA on the joint objective (Sec. VI, E2), that the cost-optimal and
robustness-optimal threshold separations are actually different (E12), and
that conjunctive quorum actually beats noisy-OR fusion on security and on
total cost (E13), and that the stranger-halt property changes hands between
the two stop categories (E14). It also covers the four artifact-only
experiments (E8-E11) on exactly the same footing. These are the claims most likely to silently break if
the simulation is ever refactored, which is exactly why the script exists —
see its module docstring for the history of why it was written.

All Monte Carlo randomness is explicitly seeded (see `RNG_MASTER_SEED` and
the per-experiment seed offsets in `raga_experiments.py`); a fresh run should
reproduce the reference data in `dataset/` exactly. The one exception is E9
(decision throughput), which is a wall-clock timing measurement. E9 reports it
as an order-of-magnitude comparison for exactly this reason, and
`verify_paper_claims.py` checks only the order of magnitude, not the exact
number. The paper itself now quotes only the measured per-decision latency.

### Reference data

`dataset/` contains the CSVs from one verified run (all 141 checks passed
against the current manuscript). This is included so a reviewer can inspect
the exact numbers behind every table without spending the ~3 minutes to
regenerate them, and to make it easy to spot if a future code change causes
the data to drift from what's committed here. Regenerating is still
recommended before trusting the artifact — see above.

## 2. The physical testbed

The paper's Sec. VI (E6-E7) describes implementing "the decision logic as a
stdlib-only Python node on three Android phones over UDP with
HMAC-SHA256-signed envelopes." The three nodes are one generator and two
device agents (CRITICAL robot, LOW lamp). That code lives in `testbed/`:

```
testbed/common.py                shared config, threshold math (Eqs. 2-4), envelope sign/verify
testbed/generator.py             Tier 2 node: builds and broadcasts a signed authority envelope
testbed/device_agent.py          Tier 3 node: Algorithm 2, run independently per device
testbed/trigger_hazard_event.py  stands in for a device's own hazard detection, for testing ERLC
testbed/run_local_demo.sh        end-to-end demo on localhost, no phones required
testbed/test_matches_parameters.py  checks testbed/common.py agrees with parameters.py
```

`testbed/common.py` restates the cost matrix literally rather than importing
`parameters.py`, so the directory runs on a phone with nothing but the standard
library. `test_matches_parameters.py` guards that duplication — run it after
changing either file.

Every file in `testbed/` uses only the Python standard library (`socket`,
`hmac`, `hashlib`, `json`, `argparse`, `threading`) — no `pip install`
needed, so it runs unmodified under Termux's stock `python3` exactly as
described in the paper.

### Quick check (no hardware required)

```bash
cd testbed
bash run_local_demo.sh
```

This starts two device-agent processes on localhost (the lamp and the robot
arm) and drives them through the paper's reported testbed observations,
printing each decision and appending it to a `.jsonl` log:

1. An unenrolled visitor (`c = 0.001`) halts the **CRITICAL** robot arm →
   `EXECUTE` (`T_eff = 0.00072`, matching Table I's `T_res` for that class).
2. The same visitor cannot halt the **LOW** lamp → `WITHHOLD`
   (`T_eff = 0.33866`, again matching Table I).
3. The same halt on the same lamp, ~0.4 s after a hazard event is registered
   on that lamp's own timeline, falls inside the ERLC reflex band →
   `EXECUTE` at `T_eff = 0.00034`.
4. An otherwise identical `CRITICAL` agent started with `--emergency-stop`,
   i.e. whose needless-stop cost is 60 s of line time rather than 2 s,
   **refuses** the same visitor's halt at `T_eff = 0.02119`. This is E14 made
   physical: bystander halt authority over the most dangerous machine is
   bought with restart speed, not granted by the authorization policy.

### Running on real hardware (e.g. three Termux phones)

Run one `device_agent.py` per device on its own phone, and `generator.py` on
a third, pointing `--agents` at the device phones' LAN IP addresses instead
of `127.0.0.1`. See each script's `--help` for the full option list; the
options and defaults match the parameters in Table I and Eqs. (2)-(4) of the
paper.

The reflex-band leniency multiplier (`epsilon` in Eq. (4)) is set to
`c_floor = 1e-3` in `common.py`; this value is back-computed from the paper's
own reported measurement (a halt threshold of `T = 0.00033` on the lamp,
`T_res = 0.33333 * epsilon`), not independently asserted — see the comment
in `common.py` for the derivation. The `TemporalWindow` staleness bounds are
implementation choices the paper explicitly does not fix numerically
(Sec. V-F: "we neither evaluate it separately nor claim it as a
contribution"); the defaults here are documented as such and are safe to
override with `--res-window` / `--perm-window`.

Conjunctive quorum (`--c-second` on `generator.py`) is included as an
extension for anyone who wants to exercise the corrected quorum design
(Sec. VI, E13) on physical hardware too — the paper's own three-phone trial
tested only the threshold inversion and ERLC, not quorum.

## Two things that look like bugs but are not

**E2 and E13 use different polarity mixes.** In `draw_event` (E2) strangers
issue restrictive commands 85% of the time — a bystander is far more likely to
be halting something than starting it. E13's `run` draws polarity uniformly for
every actor, which is the more adversarial assumption and roughly triples
unauthorized permissive volume. That is why uniform-loose security failures are
1975 in Table II and 3754 in Table III on what otherwise look like identical
configurations. The paper's Table III caption states this; the counts are not
meant to be compared across the two tables.

**E12's separation exponent is `g` in the code and `s` in the paper.** The paper
renames it to avoid colliding with Eq. (4)'s ERLC multipliers `g_res`/`g_perm`.
The CSV column stays `g`.

## Scope

The physical testbed validates *distributed decision behaviour*, not sensing:
identity confidence is injected on the command line and no gesture recogniser
runs in the loop. That is why gesture polarity error appears throughout this
artifact as a swept axis rather than a measurement, and why its sweep is
anchored on a published benchmark rather than on our own hardware.

The reflex-band values are borrowed from *braking* responses to surprise road
hazards, the best-characterised human hazard-reaction data we could find;
measuring the band for *gestural* responses on deployed hardware is the main
outstanding measurement, and the paper says so.
